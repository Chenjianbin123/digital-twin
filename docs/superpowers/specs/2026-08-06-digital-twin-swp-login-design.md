# 数字孪生 SWP 登录与 Token 接入设计

## 目标

为数字孪生项目增加与现有 UI 一致的登录门禁，复用 `swp-admin` 的登录、角色确认和 Token 请求协议。未认证时不得初始化真实病区数据；认证并选择角色后才进入护士站。

## 登录页面

采用“右侧值班门禁”方案：

- 全屏使用现有高精度护士站预览图作为主视觉，不提前启动 3D 场景与接口请求。
- 左下显示“智慧病房数字孪生”和实时空间态势标识。
- 右侧使用全高深色操作轨，包含账号、密码、密码显隐、登录状态和主操作按钮。
- 登录成功但存在多个角色时，右侧操作轨原位切换为角色选择步骤。
- 移动端改为底部或全宽操作区，保证表单不遮挡品牌标题且所有文字可完整显示。
- 不提供“记住密码”，不把明文密码写入任何浏览器存储。

## 认证流程

1. 用户输入账号和密码。
2. 前端使用与 `swp-admin` 一致的 MD5 结果提交密码。
3. 调用 `POST /swp/system/sysUser/login`，请求体为 `userName`、`userPassword`。
4. 登录成功后保存返回的用户信息，并将 `data.token` 写入 `sessionStorage.TokenKey`。
5. 如果账号有多个角色，用户选择角色；只有一个角色时仍显示确认步骤，避免以错误身份进入。
6. 调用 `POST /swp/system/sysUser/roleConfirm`，请求体包含 `roleId` 与当前 Token。
7. 角色确认成功后写入当前角色会话，挂载数字孪生主界面并加载病区列表。

## Token 与请求生命周期

- 新增独立认证会话模块，负责读取、写入和清除 `TokenKey`、用户信息与当前角色。
- SWP 业务请求优先读取 `sessionStorage.TokenKey`，通过 `token` 请求头发送。
- 登录请求明确跳过 Token 注入，防止使用旧 Token 或环境静态 Token。
- 接口业务码 `403` 或 HTTP `401/403` 时统一清除认证会话，并通知应用壳层返回登录页。
- 退出登录时停止远程轮询、清空数字孪生业务状态和认证会话，再显示登录页。
- 不复制 `swp-admin` 的明文密码存储、整棵状态树持久化和仅检查 Token 字符串的路由守卫缺陷。

## 应用结构

当前项目没有 Vue Router，因此使用根应用门禁：

- `App.vue` 只负责在认证门禁、启动加载器和数字孪生主界面之间切换。
- 登录和角色选择封装为独立组件。
- 认证 API、认证状态和通用请求鉴权分别放在独立模块中。
- 现有病区选择与 3D 场景代码保持不变，只调整其启动时机。

## 数据源

- 开发环境切换为 `VITE_DATA_SOURCE=remote`。
- 沿用当前 `VITE_DEVICE_HOST` 和 Vite `/swp` 代理。
- 登录后由用户 Token 替代前端静态 Token 访问真实 SWP 接口。
- 环境 Token 仅作为兼容配置，不用于已登录会话。

## 错误处理

- 登录失败显示后端消息，但不暴露接口响应、Token 或调用栈。
- 网络超时与服务不可达显示可重试状态。
- 无角色账号停留在登录门禁并提示联系管理员。
- 角色确认失败不进入数字孪生主界面。
- 会话失效返回登录页，并显示“登录已过期，请重新登录”。

## 测试与验证

- 测试密码摘要、Token 会话读写和清理。
- 测试登录请求不携带旧 Token，业务请求携带当前 Token。
- 测试业务码与 HTTP 状态码 `401/403` 会触发会话失效。
- 测试多角色必须确认后才进入主界面。
- 测试未登录时不会加载病区和真实设备数据。
- 运行现有边界测试、TypeScript 检查和生产构建。
- 使用浏览器验证桌面端与移动端登录页、角色选择、错误态和退出登录。
