# 护士站真实接口数据源设计

## 目标

将开发环境从本地 `mock` 数据切换到智慧病房设备后端的 `remote` 数据源，让护士站、病区走廊和病房内部统一展示真实病区、房间、床位、患者、设备与环境数据。

## 接入方案

- 将 `.env.development` 中的 `VITE_DATA_SOURCE` 从 `mock` 改为 `remote`。
- 沿用现有 `VITE_DEVICE_HOST`、`VITE_API_TOKEN` 和 Vite `/swp`、`/swp_upload` 代理配置。
- 沿用现有病区选择流程：先请求医院病区列表，再按用户选择的 `areaId` 查询门口机及其详情。
- 继续通过现有归一化层把接口响应转换为 `TwinAreaEntity`，不让页面和 3D 场景直接依赖后端原始字段。
- 继续启用远程服务：环境数据每 30 秒轮询，病区基础数据每 60 秒刷新。

## 数据流

1. 页面启动后通过 `fetchHospitalAreas()` 获取可用病区。
2. 用户选择病区后，通过 `fetchDoorDeviceList({ areaId })` 获取门口机列表及详情。
3. `mapDoorListToTwinArea()` 将接口数据转换为统一数字孪生模型。
4. Pinia store 驱动护士站指标、3D 屏幕、走廊和病房详情更新。
5. 后台轮询持续更新环境与病区基础数据，并保留当前场景位置。

## 错误处理

- 远程接口不可达、超时、鉴权失败或返回空数据时，在页面展示现有错误信息。
- 不自动回退到 `mock`，避免用户把假数据误认为真实数据。
- 单个门口机详情失败时沿用现有部分成功策略，并显示数据警告。

## 安全与范围

- 不新增或修改 Token，不在日志与页面中显示鉴权信息。
- 不修改护士站模型、屏幕布局、相机、面板或业务交互。
- 不新增依赖，不修改后端接口协议。
- 仅修改开发环境数据源配置，并增加配置契约测试。

## 验证标准

- 配置契约测试确认开发环境使用 `remote`，且 Host 与 Token 已配置为非空值。
- 现有远程接口查询契约测试通过。
- TypeScript 检查与生产构建通过。
- 开发服务启动后页面标识为“实时数据”，且能加载病区选择或给出明确的真实接口错误。
