# 护士站屏幕信息优化设计

## 目标

优化高精度护士站场景中前台四台电脑与后墙信息设备的显示内容，解决当前文字旋转、画面裁切、信息重复、层级混乱和远距离不可读问题。模型结构、护士台尺寸、相机控制、业务面板和病房场景保持现状。

## 视觉方向

采用用户确认的 B「分工指挥台」方案。

- 所有工作屏使用统一深色底、冷白正文和青色主强调。
- 青色表示正常，黄色表示需关注，红色只表示需要立即处理的事件。
- 取消无意义装饰线、过小文字、重复标题和同屏过多卡片。
- 每块屏最多显示三个重点信息块；远景优先显示数字、房号和短状态词。
- 字号按屏幕物理尺寸设计，不以桌面 UI 的信息密度直接缩小复制。

## 屏幕分工

### 后墙设备

- 中央主屏：病区总体态势，显示在床数、待处理呼叫、输液巡视、设备在线率和当前时间。
- 左侧屏：值班与公告，显示护士长、责任医生、静音时段和一条公告。
- 右侧屏：重点事件，按呼叫、设备离线、环境异常的优先级展示，最多三条。

后墙只负责抬头查看全局，不提供详细任务列表。

### 前台四台电脑

- 电脑 1：任务队列，显示紧急数量、待处理数量和最高优先级任务。
- 电脑 2：病房状态，显示前三个重点病房的房号、状态和床位占用。
- 电脑 3：床位与输液监测，显示在床、空床、输液中和待巡视数量。
- 电脑 4：设备健康与环境，显示在线率、离线设备数和环境预警数。

前台电脑负责低头处理任务，不重复后墙的完整总体概览。

## 渲染与模型适配

现有 `Screen_Work_01` 至 `Screen_Work_04` 是有厚度的盒体网格，直接替换其材质会沿用盒体 UV 图集，造成内容旋转、缩放和裁切。优化后不再把完整 Canvas 纹理直接贴到盒体材质上。

- 保留原屏幕盒体作为黑色边框和暗色底面。
- 为每块显示器创建与可视表面尺寸匹配的独立平面，使用标准 0-1 UV。
- 平面略微前移，避免 Z-fighting，并关闭不必要的深度写入。
- 每块屏幕显式绑定自己的内容类型，不再复用左右两套纹理制造四种职责。
- 后墙额外屏幕改为左、中、右三种明确内容，删除前后台重复映射。

## 数据与刷新

所有数字继续来自当前 `area`、`roomSummaries` 和设备状态，不新增接口。

- 数据变化或病区切换时重新生成 Canvas 纹理。
- 时间按现有刷新机制更新。
- 无数据时显示短句“暂无待处理任务”或数值 `0`，不保留空白卡片。
- 患者姓名不进入后墙总体屏；前台若需展示床位任务，仅使用现有脱敏名称规则。

## 错误与回退

- 如果指定屏幕对象不存在，只跳过该屏并输出现有警告，不影响 GLB 场景加载。
- 如果覆盖平面创建失败，保留暗色屏幕底面，不显示错位纹理。
- 视频宣教屏保持现状，不纳入工作屏信息重复链路。

## 验证

- 增加边界测试，校验四台前台电脑和三块后墙屏的职责映射。
- 增加覆盖平面创建约束，防止恢复为直接替换盒体材质。
- 运行护士站相关测试与生产构建。
- 在桌面和移动视口进行视觉检查，确认没有旋转、镜像、裁切、重叠或过小文字。
- 截取正式护士站效果图供用户确认。

## 不做

- 不修改 GLB、Blend 源文件或护士站模型比例。
- 不调整相机旋转、缩放和边界限制。
- 不修改右侧业务面板、病房走廊或病房内部。
- 不新增接口、依赖、动画或可点击的 3D 屏幕交互。
