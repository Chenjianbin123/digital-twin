# 护士站真实数据分屏展示设计

## 目标

将护士站 3D 模型中的信息屏统一接入当前病区真实数据，覆盖床位、患者、呼叫、输液、设备在线状态和环境告警。屏幕内容由当前 `TwinAreaEntity` 派生，不新增重复接口。

## 数据来源

页面沿用现有病区加载和刷新链路。护士站屏幕只消费 `AreaScene` 已收到的病区数据和 `RoomSummary` 汇总结果：

- 病区、科室、病房名称来自当前病区实体
- 床位总数、在床、空床、占用率来自病房床位数据
- 呼叫和输液数量来自床位状态汇总
- 设备在线、离线状态来自床位及设备状态
- 环境预警来自病房环境数据
- 值班人员仅在真实字段存在时展示；缺失时显示“暂无数据”

## 屏幕职责

| 屏幕 | 内容 |
| --- | --- |
| 主屏 | 病区名称、总床位、在床、空床、占用率、呼叫数、输液数 |
| 左工作屏 | 呼叫病房、离线病房、环境异常、最高优先级事件 |
| 右工作屏 | 设备总数、在线数、离线数、在线率、环境预警 |
| 中左屏 | 病房床位占用、空床和呼叫状态 |
| 中右屏 | 输液巡视、患者状态和重点关注病房 |
| 公告区域 | 真实公告或“暂无公告”，不使用伪造固定公告 |

## 优先级

异常事件按以下顺序排序：床位呼叫、环境告警、设备离线、输液巡视、普通状态、空病房。屏幕展示优先级最高的病房，剩余病房按病房顺序显示。

## 刷新和降级

- 每次 `updateArea` 或 `syncAreaData` 后重绘护士站屏幕
- 使用现有 Canvas 贴图和材质替换逻辑，不改变模型节点和相机逻辑
- 数据字段缺失时显示“暂无数据”，不显示虚构的电话号码、探视时间或统计数字
- 刷新失败时保留上一帧有效数据，避免屏幕闪烁为空
- 新模型缺少可绑定屏幕节点时记录警告，并保留当前页面的后备显示

## 验证

- 增加屏幕数据派生的单元测试，覆盖正常数据、呼叫、离线、环境预警、空病区和缺失字段
- 运行护士站边界测试和 `npm run build`
- 启动项目后确认 5 个模型屏幕均显示病区真实数据，且切换病区后内容同步更新
