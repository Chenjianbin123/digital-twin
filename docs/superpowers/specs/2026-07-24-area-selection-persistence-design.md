# 病区选择持久化设计规格

日期：2026-07-24

## 1. 背景与目标

当前系统会在成功进入或切换病区后，将病区 ID 保存到
`ward-digital-twin:last-area-id`，但页面刷新后只在选择页高亮该病区，仍要求用户再次点击进入。

本变更要求页面刷新后自动恢复上次成功进入的病区，并在启动动画期间加载该病区数据。首次使用、保存记录失效或恢复失败时，仍展示病区选择页。

本规格覆盖原《病区选择与切换设计规格》中“刷新后仍先显示选择页、不自动进入”的规则；其余病区切换、数据隔离和权限预留设计保持不变。

## 2. 启动行为

远程数据模式下的启动流程如下：

1. 校验设备接口运行配置并初始化文件资源地址。
2. 请求当前用户可访问的启用病区列表。
3. 读取本地保存的上次病区 ID。
4. 仅当该 ID 存在于当前可访问病区列表时，自动加载对应病区。
5. 加载成功后直接进入该病区护士站，并启动该病区实时服务。
6. 没有有效保存记录时显示病区选择页，保留现有默认高亮逻辑。

自动恢复只恢复病区上下文，场景统一回到护士站；不恢复上次打开的病房、床位、相机位置或抽屉状态。

数据库和模拟数据模式保持现有启动行为，不引入病区自动恢复。

## 3. 状态与职责

Store 增加独立的 `rememberedAreaId` 状态，用来区分两种概念：

- `rememberedAreaId`：用户此前确实成功进入过、且当前仍有效的病区，可用于自动恢复。
- `preferredAreaId`：选择页的默认高亮候选，允许回退到环境配置或列表第一项，但不能触发自动进入。

`loadAreaOptions()` 在病区列表返回后解析这两个值。启动编排在病区列表加载成功后，只对 `rememberedAreaId` 调用现有 `enterArea()`，复用已有的快照加载、原子提交、本地保存和实时服务启动逻辑。

不缓存患者、床位或设备详情；每次刷新页面仍从真实接口重新加载上次病区的最新数据。

## 4. 无效记录与异常处理

- 本地没有保存记录：不自动进入，显示病区选择页。
- 保存值不是有效正整数：清除无效记录，显示病区选择页。
- 保存的病区已停用、删除或无权访问：清除记录，显示病区选择页。
- 病区存在但设备数据加载失败：保留记录，停止自动进入并显示现有进入失败提示，允许重试或选择其他病区。
- 用户随后成功进入或切换病区：用新病区 ID 覆盖本地记录。

本地记录只用于体验优化，不作为权限依据。自动恢复前必须先通过当前病区列表和访问策略校验。

## 5. 测试与验收

- 有效保存记录能够解析为 `rememberedAreaId`，并在启动时调用一次对应病区的进入流程。
- 没有保存记录时不会自动进入列表第一项。
- 无效、已删除或无权限的保存记录会被清除，并停留在选择页。
- 自动恢复失败时停留在选择页，用户仍能手动选择病区。
- 自动恢复成功后进入护士站，顶部显示的病区与保存记录一致。
- 手动切换病区后刷新，自动进入新病区。
- 病区查询和设备查询仍使用真实接口，设备请求携带恢复病区的 `areaId`。
- 病区选择页高度固定为应用视口高度，病区数量增多时页面自身纵向滚动，外层应用不被撑高。
- 选择页只存在一个纵向滚动容器，顶部栏在滚动时保持可见，桌面和移动端均不出现双滚动条。
- 现有并发切换测试、病区接口测试和生产构建继续通过。

## 6. 选择页高度与滚动

病区选择页根容器使用父应用的固定高度，并设置 `min-height: 0`，防止其内容参与撑高外层布局。根容器关闭横向溢出、开启纵向自动滚动；顶部栏沿用 `position: sticky`，病区列表、错误提示和进入按钮随页面内容滚动。

全局 `html`、`body`、`#app` 继续保持固定高度和 `overflow: hidden`，不新增第二个页面级滚动容器。移动端沿用动态视口高度，并保证进入按钮能够通过滚动到达。

## 7. 非目标

- 不恢复护士站之外的页面位置或操作状态。
- 不增加“记住我的选择”开关。
- 不增加登录角色或服务端权限实现。
- 不修改现有病区切换界面和 3D 场景结构。
