# 新医院走廊模型替换设计

## 目标

将项目当前病区走廊的静态 GLB 替换为 `hospital-in.glb`，同时保留现有的业务动态层：门口屏模板解析、房间状态和告警刷新、门口状态灯、病房点击进入、相机与场景切换逻辑。

## 资产与坐标

- 将新文件复制为 `public/models/hospital-corridor/hospital-in.glb`，通过版本查询参数加载。
- 新 GLB 使用 Blender 的 Z-up 坐标，Three.js 场景使用 Y-up；加载后绕 X 轴旋转 `-PI/2`。
- 依据导入后包围盒把模型平移到场景原点：水平中心对齐到 `(0, 0)`，地板最低点对齐到 `Y=0`。不改变模型比例。
- 模型尺寸约为 `44.1m × 31.0m × 3.7m`，新相机参数从模型包围盒计算，不复用旧走廊固定长度假设。

## 门与动态层映射

新模型中识别以下六个门网格：`门1`、`门2`、`门2.001`、`门3`、`门4`、`门5`。按门的空间位置沿走廊主轴从近到远排序，映射到病房槽位 `0–5`。

加载适配器负责：

1. 为六个门写入 `userData.roomIndex` 与 `userData.role='wardCorridorDoor'`。
2. 根据门所在墙面和走廊中心计算朝向，在门上方生成动态门口屏、房间标签和状态灯的挂载点。
3. 复用现有 `renderDoorTerminalTexture`、模板缓存、状态摘要和刷新 token，不把实时纹理烘焙进 GLB。
4. 对不存在的门节点记录警告并跳过该槽位；GLB 加载失败时继续使用现有生成式走廊回退，不阻塞病区进入。
5. 当房间数量超过六个时，仅绑定前六个槽位并隐藏/忽略多余房间的走廊门交互，避免生成旧模型外壳与新模型重叠。

## 场景可见性与交互

- 新模型加载成功后隐藏旧的生成式走廊和旧病房外壳。
- 动态门口屏使用 `MeshBasicMaterial` 覆盖层并保持较高 renderOrder，避免被新模型材质遮挡。
- 射线检测先命中新模型门网格，再通过 `roomIndex` 触发现有 `onRoomClick`；屏幕和状态灯不独立触发房间点击。
- 病区切换、实时状态更新和离开场景时，沿用现有的绑定刷新与资源释放路径。

## 相机与验证

- 新增基于包围盒的走廊总览相机：目标点取走廊中心偏上，位置位于入口内侧，限制上下角度避免穿过地板或顶板。
- 保留现有护士站到走廊的过渡接口，仅替换走廊阶段的目标位置。
- 单元测试覆盖：六门识别/排序、坐标归一化、缺失门容错、超过六个房间的截断规则。
- 运行 `npm run build`，并通过本地浏览器验证：模型加载、门口屏显示、状态刷新、六扇门点击和回退路径。

## 变更范围

- 新增走廊 GLB 资源。
- 修改走廊模型 URL、模型适配与相机计算代码。
- 增加针对门映射和坐标适配的测试。
- 不修改护士站模型、病房内部模型和后端数据接口。
