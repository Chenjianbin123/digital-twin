# 真实接口优先数据源设计

## 目标

项目在开发和生产环境中默认连接智慧病房后端 `192.168.96.104`。只有显式配置 `VITE_DATA_SOURCE=mock` 时才允许加载模拟数据，避免生产构建因缺少环境变量而静默切换到 Mock。

## 数据策略

- 默认数据源由 `mock` 改为 `remote`。
- 开发环境和生产环境均显式配置 `VITE_DATA_SOURCE=remote`、`VITE_DEVICE_HOST=192.168.96.104`。
- 登录 Token 继续由登录接口写入 `sessionStorage.TokenKey`，所有业务请求继续复用该 Token。
- 病区、门口机、病房、患者、床位、环境、设备详情、模板和医院信息均以真实接口返回值为准。
- 真实接口失败时不得注入模拟患者、床位、呼叫、状态或环境数据，应保留原数据或显示错误/空状态。
- 模板接口失败时允许使用本地固定布局展示已经取得的真实业务数据；该布局属于展示降级，不包含 Mock 业务数据。
- 状态、呼叫和环境模拟器只允许在显式 `mock` 模式启动。

## 配置与数据流

浏览器请求 `/swp/*`，由 Vite 代理到 `http://192.168.96.104:9700/swp/*`。应用登录后先读取真实病区列表，用户选择病区后调用门口机列表接口，再按设备编号加载门口机详情、床头机详情和模板。环境数据独立定时刷新，病区数据定时重新拉取。

未配置 WebSocket/SSE 地址时，不生成模拟实时事件，继续使用真实接口轮询。后端提供实时地址后再通过 `VITE_REALTIME_URL` 接入。

## 错误处理

- 缺少或错误的数据源配置不再静默进入 Mock，而是使用 `remote` 并由登录/接口层给出明确错误。
- 接口鉴权失效时清理登录会话并返回登录页面。
- 单个床头机模板 ID、环境数据或医院信息加载失败时，不影响其他真实病房数据展示，但不得补入对应 Mock 数据。

## 验证

- 为数据源解析增加测试：缺失或非法配置默认 `remote`，只有明确的 `mock` 返回 `mock`。
- 验证开发与生产配置均指向真实接口。
- 运行相关单元测试、类型检查和生产构建。
- 启动项目后确认登录页、病区选择及网络请求均使用 `/swp` 真实接口。
