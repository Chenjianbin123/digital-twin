# 真实接口数据链路优化实施规划

> 本阶段先整理并稳定病区、门口机和模板数据链路，后续再扩展护士站数据模型与 3D 性能优化。

**目标：** 让真实接口调用可追踪、失败可定位、Mock 仅在明确配置时使用。

**范围：** HTTP 请求观测、医院信息错误状态、门口机模板预加载告警、数据源回归测试。

## 实施顺序

1. 在 `src/api/http-client.ts` 增加最近请求记录能力，记录路径、耗时、状态和错误，不记录 token 或请求体敏感信息。
2. 在 `src/api/hospital-info.ts` 保留严格查询函数，让 store 能把医院信息失败转换成明确告警。
3. 在 `src/stores/twin-store.ts` 统一使用严格查询结果，避免医院信息接口失败被静默吞掉。
4. 增加边界测试，覆盖请求观测、医院信息异常告警和 Mock 数据源显式选择。
5. 运行专项测试与生产构建。

## 已完成的第二阶段

- `queryBedDeviceInfo` 仅在进入病房内部时触发。
- 床头屏模板请求增加代际校验，离开病房或切换病房后旧结果不会写回当前床位。
- 页面显示床头屏模板加载中和失败状态。
- 离开病房立即清理床头屏加载提示。

## 已完成的第三阶段

- 护士站 3D 屏幕与右侧面板统一消费 `buildNurseStationLiveData`。
- 在线设备统计以实际设备编号和设备状态为准，不再用床位数推算设备数量。
- 呼叫、离线、环境预警、床位占用和设备在线率使用同一套口径。
- 新增护士站统一数据边界测试。

## 后续阶段

- 进入病房时再加载床头屏模板，并增加取消请求状态。
- 护士站屏幕数据统一为独立 live-data 模型。
- 增加开发环境接口调试面板。
- 对 GLB 和大体积前端 chunk 做动态分包。
