# 病房呼叫流程与后端对接缺口

## 当前已核对能力
- src/api/swp-events.ts：活动呼叫和呼叫响应时效只读查询。
- 响应记录有开始/结束、到场人员等字段，但现有类型不能确认其与活动事件的稳定唯一关联；不可按患者姓名、床名或近似时间强行关联。
- src/api/alert-ack.ts：通用确认只支持可选路径写入；未配置返回 false。现有 SWP 来源呼叫禁止通过该通道接手或结束。
- 当前未找到完整的接手命令、处理记录回读、并发竞争控制或服务端审计接口。

## 本轮完成
- 本病房 SWP 呼叫列表与一键定位，沿用 store.openAlertTask。
- 只展示当前病房匹配事件，排除其他房间、未匹配事件及非呼叫预警。
- 来源发生时间、距发生时长、最近成功同步时间；时长不代表护士未响应时间。
- 同步失败/过期/部分同步明确提示；空列表不被当作失败时的安全状态。
- 来源恢复后列表随统一事件状态更新，不新增本地解除动作。

## 后端需确认的契约（待提供，不是已存在 API）
1. 活动事件稳定 ID、病区/病房/床位及设备标识；同床再次呼叫必须可区分。
2. 接手命令：事件 ID、登录人员身份、幂等请求标识及版本；服务端授权并处理多人竞争。
3. 处理记录读取：接手人员、接手时间、阶段、提交结果与版本；刷新和换设备后能恢复一致状态。
4. 来源解除/结束：权威结束时间与事件版本；接手不能直接解除现场设备呼叫。
5. 历史关联与审计：响应记录/到场记录能稳定关联事件 ID，保留操作者、动作和服务端时间。
6. 断线重试及冲突返回约定：失败不展示成功，不重复生成接手动作。

## 后续验收
新事件→正确病区与床位→接手→第二人竞争→刷新/换设备回读→来源结束→历史查询；另测同床二次呼叫、患者更换、权限拒绝、网络失败及来源过期。

## 本轮验证
构建通过；新增 4 项边界测试通过；全量 487 项中 486 通过，唯一失败仍是原有护士站背景断言。
浏览器使用真实组件和模拟呼叫数据验证定位事件、禁用无法匹配的床位、失败保留记录、来源恢复及窄屏布局。未进行真实后端写入或多人接手验收。
